## Strongest personality and exact artifact

The tagged manual explicitly calls the Anand setup the strongest V1.1 personality and says the dedicated testers executable uses that network with personality options locked. The Linux artifact is literally named `rodent_v_1.1_testers_linux_amd6` in the zip, is 4,013,485 bytes, and has SHA-256 `9c68d7b39dc933eff5fd2da88bd4be1b0d009f6d2add7485c121cfc0d1308531`. Static inspection finds exactly one byte-identical copy of `nets/rodent_anand_512hl.bin` inside that executable. The separately shipped 789,568-byte net has SHA-256 `5f7480b56538e9e64ee02fb5b4842bf0394ee44b707dae3a63ec7f902abd0afb`; `personalities/anand.txt` has SHA-256 `b0e336bc8892043063e6b1fcc42193bbbc6cacf347e9d561d089ddcb602bf3aa` and specifies pure NNUE, scale 192, and horizontal mirroring.

Do not substitute the default `rodent_v_1.1_linux_amd6`: it embeds the different `rodent_hm_512hl_1.bin` network. Do not infer that CCRL used Anand because the CCRL page does not say so. A matched NGN comparison should use the official testers artifact because it is the release author's explicit strongest testing configuration, and should label that choice independently of the CCRL row.

The released Linux binary reports Go 1.26.1, `GOAMD64=v3`, `CGO_ENABLED=0`, and `golang.org/x/sys v0.47.0`, but its module version is `(devel)` and it contains no VCS revision. Therefore the official release-asset digest is the binary provenance boundary; the tagged source is supporting source/license evidence, not proof that the binary was reproduced from that commit.

## Admission contract

Before games, freeze the zip, exact testers member and mode, extracted member hash, tag/source archive, license, embedded-net containment receipt, hardware/ISA observation, working directory, and every UCI transcript. Run sequential `uci`, option, `isready`, legal-search, stop, new-game, and quit checks under the eventual CPU mask. Require the engine to identify as Rodent V 1.1, report the Anand NNUE loaded, remain one worker, accept the matched Hash value, search with no internal or external book, emit no operational errors, and leave no process.

Tagged source advertises Hash 1..4096, Threads 1..256, OwnBook default false, UCI_LimitStrength false, and UCI_Elo. Its `nooptions` branch and manual disagree about whether Threads remains advertised, and the strongest testers executable was produced from release-specific source changes not present as a reproducible tag diff. Treat the runtime option transcript as authoritative: do not send absent options, do not silently fall back to HCE, and do not use UCI_Elo limiting. Use a fresh empty role directory because the network is embedded and source initializes empty books; independently reject book signatures in the retained trace.
